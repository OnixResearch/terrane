- `src/hypervisor_gpa.rs` verified more cleanly when `access_gpa` kept its own linear scan instead of delegating to `lookup_memslot` and then trying to recover the chosen index across `Option<usize>` proof casts. `src/hypervisor_interrupt.rs` needed the same shape: small recursive proof helpers (`next_from_skips_to`, `next_from_all_clear`) mirroring the exec scan were much more stable than trying to prove the loop result directly from invariants alone.
- For compiler-pass proofs over cloned `RawInstr` values, whole-struct equality is brittle because `RawInstr` contains `Vec<u32>`. Compare projected views `(def, opcode, uses@)` in postconditions/invariants instead of trying to prove `cloned == original` directly.
- SSA phi-argument coverage must deduplicate predecessor blocks: `dominator_tree::predecessors` returns one entry per edge, so self-loops or duplicate edges otherwise create duplicate phi args for the same predecessor.
- Nix Base32 gotcha for `openspec/changes/nix-derivation-primitives`: upstream `BaseNix32::decode` accepts non-canonical alphabet strings, so `decode(encode(x)) == x` is valid but `encode(decode(y)) == y` only holds for canonical encodings (`"0" -> [0x00] -> "00"`, `"z" -> [0x1f] -> "0z"`).
- The in-progress `src/nix_base32.rs` worktree no longer needs closeable base32 trusted boundaries: the canonical roundtrip proof, `encode`, and `decode` are all internalized now, so older notes that counted 1, 2, or 3 base32 trusted boundaries are stale.
- Base32 proof scaffolding that already verifies: `reconstruct_prefix_spec`, `decode_prefix_of_encode`, and `bit_at_padded_bounded`. For `by(bit_vector)` lemmas over shifted bytes, bind the shift count to a `u64` local first; inline `(pos % 8) as u64` can trigger `IntRange` failures.
- The base32 content-equality path now has verified local update lemmas for both cases: `current_byte_update_no_spill`/`next_byte_zero_when_no_spill` for `bit % 8 <= 3`, and `spill_digit_formula_j4`..`j7` plus `current_byte_update_spill`/`next_byte_update_spill` for spill cases. These verify best when the relevant `Seq` bytes and masked-byte expressions are first bound to local `u8` variables before any `by(bit_vector)` step.
- `encode_decode_roundtrip` is now fully internalized in `src/nix_base32.rs`. The key bridge was `reconstruct_prefix_masked`, which proves `extend_to_spec(reconstruct_prefix_spec(bytes, upto), bytes.len()) == prefix_masked_bytes_spec(bytes, upto)`, combined with `prefix_masked_full` and `reconstruct_full_len`.
- The `encode` exec wrapper can also be internalized cleanly by avoiding the old left/right byte formula in proofs: add a verified exec helper `bit_at_padded_exec`, build `encode_digit` from five padded bits, and map digits with a tiny verified `alphabet_char` helper. This required a precondition `bytes@.len() <= ((usize::MAX as int) - 4) / 8` so the expanded output length and `bit + 4` window stay in `usize` range.
- The `decode` exec wrapper can be internalized without loop invariants by switching to a recursive helper `decode_prefix_exec` that mirrors `decode_prefix_spec` exactly. The hard update step becomes manageable if you first internalize `extend_to_exec` and `or_extend_at_exec`, then build `decode_step_exec` out of those pure vector constructors.
- `src/type_unification.rs` verifies more cleanly as a fuel-bounded equation-list solver (`solve_fuel`) than as direct recursive Robinson unification on `(t1, t2)`: the App/App second recursive call can grow after substitution, so a raw `type_size(t1) + type_size(t2)` decreases argument fails. Useful proof helpers were `apply_subst_to_eqs_index`, `singleton_subst_irrelevant_if_absent`, and lifting equation satisfaction through `compose_subst_spec`.
- `src/zircon_job.rs` internalizes subtree membership cleanly with a root-first exec helper: check `job == root` before zero-fuel failure, then prove exec fuel `job` matches the public spec's `job + 1` fuel. This avoids a `usize` overflow obligation on `job + 1` in exec code.
- `src/surelock_lockset.rs:prepare_lockset` verifies more cleanly if the exec contract only promises canonical sort shape (`strict_id_order_spec`, `no_duplicate_ids_spec`, and matching length). Trying to also prove full membership preservation and same-level rejection directly in the exec postcondition made Verus brittle; keep those behaviors covered with helper specs/tests instead.
- `src/set_associative_lookup.rs` needs explicit full-width geometry handling: branch `bits == 64` in masks, branch `shift == 64` in shifts, and use small helper lemmas (`extract_*_full_width`, `fits_zero_bits_zero`) instead of asking Verus to simplify raw `1u64 << 64` / `addr >> 64` / `tag << 64` paths.
- `src/sel4_vspace.rs` verified most cleanly when map used two records: a zero-rights candidate for alignment/non-overlap checks and failure proofs, then the final installed mapping with masked rights only after the scan. Making the overlap proof talk about the exact candidate shape was far easier than proving the failure path against the post-mask record directly.
- `src/sel4_invocation.rs` verified cleanly only after capability-kind checks stopped using direct enum `==` / `!=` on `CapKind`. Give Verus small match-based `is_*_kind_spec(...)` helpers for spec code and use `matches!(...)` in exec code; otherwise it tries to reason through the derived `PartialEq` impl and asks for an assume-spec bridge.
- `src/sel4_invariants.rs` endpoint-step preservation closed much more cleanly once the wrappers required a `Running` sender (not generic runnable-or-running), kept endpoint↔TCB correspondence as explicit wrapper preconditions for the head receiver, and used tiny local state-kind helpers (`is_running_tcb_state_spec`, `is_blocked_on_*`, `is_runnable_tcb_state_spec`) instead of direct enum equality in proof-facing code.
- Recursive AST kernels with `Vec` branch lists can hit Verus mutual-recursion measure traps if exec->spec view helpers recurse through both the AST and branch vectors (`global_view`/`gbranches_view`, `local_view`/`lbranches_view`) while projection helpers recurse over both choreographies and branch folds. Pick one numeric decreases surface up front, or use non-mutual / fuel-indexed wrappers before spreading those views across multiple modules.
- Choreography-model gotcha: if non-decider `Offer` branches are built from the first branch-dependent receive heads, their local labels are those receive labels, not automatically the outer global choice labels. The stronger property/step theorem “first exposed offer uses the outer choice label set” is false in nested/shared-prefix cases unless the projection algorithm explicitly threads outer branch labels (or the spec adds a stronger restriction saying the first branch-dependent receive from the decider reuses the outer labels).
- `src/choreography_projection.rs` proved more cleanly once `merge_projected_labeled_branches_spec` used a fuel wrapper over `projected_branch_suffix_size(...)`, `lookup_branch_spec` on strictly increasing labels went through a helper that starts lookup from an arbitrary `from <= k`, and `projectable_implies_projection_some` split non-decider choices into the direct `role_in_branches_spec` case versus a separate absent-role-to-`End` path.
- For choreography absent-role proofs, it was easier to add a spec helper `labeled_end_branches_from_spec(...)` and prove `project_decider_choice_from_spec(...) == Some(labeled_end_branches_from_spec(...))` than to prove branch-length/body facts separately. For `projected_branch_suffix_size`, a small `cons`/shift lemma over `seq![branch] + tail` was enough to close the common-send/common-recv size-decrease obligations.
- `src/choreography_projection.rs:merge_projected_alignment` finally closed once the proof switched to a fuel-parametric helper over `merge_projected_labeled_branches_fuel(...)`, plus tiny pointwise/strict-label lemmas for `common_send_tails_spec` / `common_recv_tails_spec`; trying to prove the whole branch-map/concat story in one big forall got stuck. Likewise, `project_decider_choice_from_pointwise` only became stable once the proof bound the recursive tail with `match project_decider_choice_from_spec(..., from + 1)` instead of asserting `... == Some(rest)` after an `unwrap()`.
- The requirement-level choreography choice-agreement property is about the first branch-dependent offer for the current choice, not any later unrelated `Offer` reachable after a full same-body collapse. Modeling it directly as `first_offer_labels_from_spec(project_endpoint_spec(...), decider)` is too strong; the stable proof surface was a dedicated helper over projected branch sets that strips common send/recv prefixes and returns `Some(branch_labels_spec(branches))` only when the current choice actually exposes an offer.
- For choreography `check-ensures` work on branch-recursive exec fns, the stable pattern was: factor the branch scan into a private helper over `&[Branch]` with a direct conjunction postcondition, then let the public recursive fn reveal an open recursive result spec and delegate the choice/offer arm to that helper. Closed intermediary branch-spec wrappers and borrowed `*local`/`*global` equality assertions were much less stable.

## Proof audit hotspots
- Trusted boundaries are not limited to `external_body`: the real `assume(...)` soundness oracles are now gone, and there are no remaining `@verified-logic:no-ensures` / placeholder surfaces in `src/`.
- A prior Tracey run recorded `0 uncovered` and `0 untested`. Inspect current outputs before claiming a fresh pass.
- The recent Tracey drift was cleared with metadata-only fixes: add `r[verify]` tags for untested rules, and add `r[impl]` tags to spec-level implementations when a requirement has no separate exec fn (for example `query_cost::index_scan_cost_spec` and `snapshot_isolation::si_allows_commit_spec`).
- The temporary `src/mesi.rs` (6) and `src/page.rs` (1) trusted boundaries from the 2026-04-08 remediation are now closed; stale notes or inventories that still count MESI/page `external_body` sites are wrong.
- `src/mesi.rs:check_system_invariant` verifies best as a direct prefix-scan with prefix invariants, not by post-hoc count summaries.
- For one-line cache-protocol extensions like `src/moesi.rs`, direct pointwise `Seq::new(...)` transforms for "snoop every cache" / "invalidate every non-writer" were much easier to verify than recursive scan specs because index-level result facts fall out immediately and refinement proofs can stay pointwise.
- `src/mesi.rs:invalidate_others_spec` closed cleanly with small recursive lemmas for length preservation, unchanged indices below `from`, writer preservation, and target-index invalidation.
- Keep MESI exec paths iterative. A recursive exec helper over cache entries verifies, but it is a runtime regression because recursion depth grows with `caches.len()` and can blow the Rust stack.
- `src/page.rs:radix_index_bounded` closed with a tiny bit-vector helper over `(value >> offset) & ((1 << width) - 1)` plus an explicit arithmetic proof that the computed offset is `< 64`.
- `src/topo_sort.rs:is_topo_order` no longer needs an `assume(...)` oracle. The stable proof shape was: keep the runtime checker iterative, add recursive bridge lemmas from pointwise/pairwise facts to `all_in_range_spec` / `all_distinct_spec` / `edges_forward_spec`, and make the edge-position scans record the first matching index by guarding updates with `pu == n` / `pv == n`.
- `src/reachability.rs` closed once `reachable_spec` stopped pretending the fixed budget `n` was the essence of the property. The clean model is existential reachability (`exists fuel. reachable_fuel(...)`), after which edge extension is the true lemma: `reachable_fuel(src, u, fuel)` plus `(u, dst)` yields `reachable_fuel(src, dst, fuel + 1)` with no `assume(...)` corner case.
- `src/nix_closure.rs` closed only after an API redesign. The old `&dyn Fn` interface was not meaningfully verifiable, so the closeable gap disappeared by switching the runtime API to a finite operator table `Vec<(u64, Vec<ClosureItem>)>`, replacing the placeholder spec with a real closure predicate over reachable keys and closure-closed results, and keeping the runtime executor as an ordinary Rust wrapper outside `verus!`.
- `src/cache_hierarchy.rs` verified most cleanly by copying the `src/free_list.rs` removal pattern: prefix-recursive `remove_prefix_spec` with guarded decreases, loop-step unfold assertions in the exec remover, and small witness lemmas for "append preserves other members" / "remove excludes the target" before proving the inclusive/exclusive invariants.
- Verus here does not model slice `.to_vec()` in exec code. For verified clone/copy helpers over `&[u64]`, `&[BeamMessage]`, or similar slices, build the result with an explicit loop and an invariant over `subrange(0, i)` instead of calling `.to_vec()`.
- For structs containing `Vec`, Verus often fails to prove whole-struct equality after cloning the vector field. Prefer fieldwise postconditions (`pid/state/...` plus `heap@ =~= old.heap@`) over `result == spec_struct` unless the struct is entirely copy-like.
- For small BEAM-style value models without a global allocator, phrase heap-isolation requirements in terms of distinct pids rather than globally fresh process creation. `heap_id = pid` is a sound model only when the requirement text says distinct pids imply distinct heap identities.
- Done review checks cross-module `properties.*` rules against the prose in `docs/requirements.md`, not just the rule IDs. If the requirement mentions unlink state, exact-once delivery, or cleanup roundtrips, the property spec must carry those same state variables and quantify that behavior explicitly.
