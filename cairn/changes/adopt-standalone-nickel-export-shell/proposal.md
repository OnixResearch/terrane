## Why

Trellis has several Rust and Nix checker shells that invoke external Nickel, compare generated bytes, and enforce negative policy fixtures. `OnixResearch/nickel-export` now provides one independently versioned external shell and evaluator-neutral core at immutable revision `257fafc1c746f1faf156207043a4c826bfb16d49`. Reusing that infrastructure can remove duplicate export mechanics, but Trellis must retain proof-policy meaning, Verus gates, proof-corpus claims, and fixture authority.

## What Changes

- Pin the standalone Nickel export repository and toolchain closure to the exact published revision. r[trellis.nickel_export_cutover.source]
- Introduce a thin checker-shell adapter for exact export identity and check mode without adding filesystem or process authority to verified modules. r[trellis.nickel_export_cutover.boundary]
- Preserve Trellis verification policy, proof semantics, Verus gates, generated destinations, and fixture expectations. r[trellis.nickel_export_cutover.authority]
- Dual-run verification-policy bytes, lifecycle YAML, JSON artifact contracts, and invalid fixtures through the legacy and standalone paths. r[trellis.nickel_export_cutover.dual_run]
- Keep existing checker scripts authoritative until every positive and negative fixture agrees under the pinned evaluator cohort. r[trellis.nickel_export_cutover.rollback]

## Impact

- **Shared dependency**: exact Git revision `257fafc1c746f1faf156207043a4c826bfb16d49` of `github.com/OnixResearch/nickel-export`.
- **Trellis surfaces**: policy checker scripts, Nix checks, checked generated artifacts, dependency pins, and migration evidence; proof modules remain unchanged.
- **Authority**: Trellis remains the sole owner of verification policy, proof-corpus semantics, Verus gates, and release decisions.
- **Claims**: migration proves checked export-byte, identity, diagnostic, and freshness compatibility only. It does not prove evaluator equivalence, proof correctness, policy correctness, build correctness, or release eligibility.
